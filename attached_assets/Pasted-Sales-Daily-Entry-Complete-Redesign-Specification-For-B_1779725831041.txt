4. Validation & Business Rules
Required Fields

Branch, Date, Shift, Cashier, Total Sales
Cash POS and Cash Actual (or at least one payment method entered)
Electronic signature before final save

Auto-Calculations

average_invoice = total_sales / invoice_count
cash_diff = cash_actual - cash_pos
card_diff = card_actual - card_pos (per network)
delivery_net = total × (100 − commission_pct) / 100
total_collected = cash_actual + Σ(card_actual) + Σ(delivery_total) + credit_total
final_difference = total_collected − total_sales

Tolerance Logic

Default tolerance: ±10 ر.س (configurable per branch)
If |final_difference| ≤ tolerance → allow save with note
If |final_difference| > tolerance → require manager approval or written reason
Cannot finalize while any "pending" entry exists (e.g., card POS without actual)

Status States per Day

Draft (مسودة): saved but not signed
Pending review (قيد المراجعة): signed by cashier, awaiting manager
Approved (معتمد): manager approved
Disputed (محل خلاف): difference exceeds tolerance, requires resolution


5. UX Micro-interactions

Live calculation: every number updates instantly on input
Color-coded diff feedback: green=match, amber=small diff, red=large diff
Tab badges: update in real-time as user fills sections
Inactive rows: opacity 0.6 + dashed border for unused networks/companies
Auto-save draft: every 30 seconds
Confirmation modal before "Sign & finalize" — show summary, then signature pad
Print view: simplified single-page layout of Section 6 only

8. Replit Build Instructions
Goal: Build a single-page React app that replicates the design above.
Recommended setup:

React 18 + Vite
Tailwind CSS (configure direction: rtl globally)
lucide-react or @tabler/icons-react for icons
A signature pad library: react-signature-canvas
Date picker: native <input type="date"> is fine
State management: useState is sufficient for a single form; can lift to Context if needed
Form: build as one controlled form, store all values in a single state object matching the data model

Build order:

Set up Tailwind with RTL + color tokens from Section 1
Build the 6 sections as separate components, top-down
Add live calculations as derived values (not stored state)
Add tab logic for payment methods
Add the dynamic Summary Dashboard (Section 6) that recomputes from form state
Add validation rules from Section 4
Add sticky footer with signature modal

Accessibility:

All inputs must have <label> (visually or sr-only)
Tab order must follow RTL reading order
Color is not the only indicator — always pair with icon + text


End of specification.
