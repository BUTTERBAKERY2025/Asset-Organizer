**Result: not operationally certified; no live request → approve → plan link → batch flow was executed.** No application/browser session, external database, production data or deployment was used. No production migration was applied. This report records focused existing-test evidence, not sign-off.

## Safe execution

- `DATABASE_URL` in the environment points to a **non-local** host; it was never used. `SUPABASE_DATABASE_URL` was unset for every test command. Pure suites ran with both database URLs unset.
- Started a temporary PostgreSQL 16 instance bound to `127.0.0.1` and a newly created `verification` database; only the `PHASE_TWO_TEST_DATABASE_URL` local connection was passed to `tests/phase-two-link.migration.integration.test.ts`. That test creates its own isolated schema, applies migration `044` there, and drops the schema. **1/1 passed.** The instance and its files were removed afterward.
- In a second temporary local instance, passed a local `DATABASE_URL` **only** to `tests/recipe-exceptions.concurrency.integration.test.ts`; it creates/drops an isolated schema and applies migration `043`. **1/1 passed.** The instance and its files were removed afterward.
- Pure suites: `advanced-production-execution`, `production-planning`, `production-coverage`, `central-kitchen-request-changes`, `recipe-exceptions.server`, `recipe-exception-flow`, `finished-production-target`, `production-coverage-ui`: **76/76 passed**. `central-kitchen-orders`, `production-planning-ui`, `central-kitchen-batch-materials`, `central-kitchen-request-change-version`: **38/38 passed**.
- An exploratory invocation including `central-kitchen-routing.integration.test.ts` with `DATABASE_URL` deliberately unset yielded **1 failed / 1 passed in that file**: its DB-backed case requires a development database. The four other files in that invocation passed; they were rerun separately and passed as reported above. This is a test-environment gap, not a demonstrated product failure. Other full-schema integration suites were **not** run: their `DATABASE_URL`-based fixtures expect pre-existing application tables and some use a transaction rollback, but neither their URL nor full-schema availability was verified as local. A rollback alone is not a safety guarantee for a non-local connection.
