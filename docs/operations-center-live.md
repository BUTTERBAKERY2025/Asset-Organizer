# Operations Center live hints

The registered-write allowlist also covers HR document edits, targets, and daily sales calculation (in addition to the queue routes below); these affect branch card projections. No dashboard/PDF read disguised as a POST is considered authoritative changed business data.

The workspace GET remains the only source of business data. `GET /api/operations-center/events?branchIds=id1,id2` accepts 1–25 **existing** branch IDs; the session must pass fresh `operations:view` and all selected IDs must be in its current branch grants. The stream sends `ready`, `invalidate`, and `scope-invalidated`, with no rows, record IDs, branch names, or business values. `ready` and `: keepalive` mean only that the connection is alive; they **do not** signal changed data. No `id:` is sent, and `Last-Event-ID` is ignored: there is no replay.

Import `useOperationsCenterLive({ enabled, branchIds, onInvalidate })` from `client/src/hooks/useOperationsCenterLive.ts`. `onInvalidate(reason)` receives `"change" | "poll" | "reconnect" | "scope-invalidated"`. Refetch the authenticated workspace GET on `change`, `poll`, and `reconnect`. On `scope-invalidated`, immediately remove prior scoped workspace data from the UI/query cache and recheck authorization before showing it again. On a branch selection change, likewise clear previous branch data immediately. The returned `{ status, lastCheckedAt, lastChangeHintAt }` supports a visible freshness/connection indicator: `lastCheckedAt` is the time a poll was requested or the stream connected, **not** the time of a successfully refreshed workspace response. Display actual data freshness from the workspace GET's own successful `dataUpdatedAt`, never from keepalives or this hook alone.

Successful 2xx synchronous writes matching the operational route allowlist produce process-local invalidation hints after the HTTP response finishes. The allowlist uses registered API prefixes (not page URLs): maintenance tickets, branch complaints, branch daily closures, cashier journals, production/quality checks, attendance/shifts/timesheets, HR leaves/advances, warehouse transfers and purchasing requests, reverse logistics, deliveries, central kitchen orders/demand/shipping, waste/display bar, and branch employees. Prefixes require an exact path-segment boundary; unrelated sibling routes and failed writes are excluded. The mutating actor's branch grants are fetched afresh from the server; any connected operations viewer with an overlapping selected branch scope may receive a hint, including a different user. Cross-branch roles with truly global grants can invalidate any authorized viewer's selected scope. No client-supplied branch ID is used to choose recipients. Before every delivery, the recipient's session, account, operations:view permission and selected branch grants are freshly checked; disconnected, revoked or failing checks receive no hint. Hints carry no actor, route, affected branch, row ID or count: they are conservative invalidations of the recipient's authorized selected query, not proof any record in that query changed. Hints to a given stream are coalesced to at most one per second to avoid query storms. Other workers are not notified by this bus. The hook polls/refetches every 45 seconds while visible, and refetches on reconnect/return to foreground; this also covers missing events, asynchronous jobs, writes outside the allowlist, and multi-instance deployment. No Redis, broker, replay log, or cross-worker ordering is provided. EventSource reconnects with bounded retry; each stream closes after five minutes, at most four concurrent streams per user and 200 per process. Keepalives every 15 seconds reload session, user state, permissions, and assigned branch grants; invalid grants/session terminate the stream. This is best-effort near-real-time UI invalidation, **not** a correctness/commit notification mechanism.

Manual security checks: anonymous and non-operations viewers get 401/403 before streaming; a user requesting an unassigned ID gets 403. Revoke operations:view, deactivate the user, remove an assigned branch, or invalidate session while connected: on the next hint or keepalive the stream must emit scope-invalidated and end (or end on a DB failure). Reconnect must reauthorize and reject a revoked user. Reconnect with Last-Event-ID does not replay events. Failed/non-2xx writes emit no hint. An allowed write hints another authorized viewer selecting the same branch, not a viewer with unrelated branch grants; neither receives row or actor details. Closing a tab removes the stream; repeated reconnects cannot exceed stream limits. Verify a second app instance only observes changes by the periodic refetch, never by assuming SSE delivery.
