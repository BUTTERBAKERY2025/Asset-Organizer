# Operations center read projection

`GET /api/operations-center` requires `operations:view`; `GET /api/operations-center/export` requires `operations:export` **and** each included source's own `export` grant. Both use the same JSON contract in `shared/operations-center.ts`. This is a read projection, not a workflow or approval API.

`branchIds` is a comma-separated list (up to 30), or `all`/omitted. Every explicit ID must exist and be authorized, otherwise the entire request fails with 403. An unrestricted request exceeding 30 branches fails with 400; narrow the scope. Branch IDs are never used to elevate module permissions. `offset` is a nonnegative queue offset, capped at 10000; `scope.limit` is 100. `coverage.truncated` indicates that a source hit its 100-record scan cap or queue pagination omitted records. A source returning exactly 100 records can therefore conservatively indicate truncation. `coverage.queue[source] = unavailable` signals a failed source query; it is not a zero.

`generatedAt` is the actual projection instant. `businessDate` uses Asia/Riyadh. `cards` reuse the branch dashboard definitions and their authorized loaders; a failed card reports `state:error`, `error`, and no metrics rather than fabricated zeroes. `metrics` contain source, definition, period, authorized branch scope, as-of, and coverage. A missing denominator (including zero recorded quality checks) yields `null`, not 0%. Percent quality is passed / all recorded checks on the same business date. Timesheet finalization is *only* evidence of finalized reports within seven days: it is not payroll clearance, pay amount, or complete employee coverage.

Queue identities are `sourceType:sourceId:step:branchId`. The same record can legitimately have different branch-facing stages; identical links are not treated as duplicates. Queue items represent source records, not inferred deadlines. `dueAt` is only populated from the persisted maintenance due date; dates like journal date, leave start date, or kitchen need date are **not** represented as enforced deadlines. Ownership is an actual recorded assignee/actor or a clearly labelled stage owner/unknown. `actions` provide read links only, and do not authorize approval. Source handlers retain final action authorization. No guessed SLA, penalty, AI priority, or parallel task state is created.

`ownerId` is the persisted assigned user ID or `null`: filter "mine" **only** by `ownerId === currentUser.id`, not the translated `owner` label. An unassigned manager-review stage remains `null`; no manager is nominated by role. Source links always include exact record IDs: maintenance `ticketId`, kitchen `orderId`, warehouse `transferId`, reverse `movementId`, delivery `deliveryId`, leaves `leaveId`, attendance `attendanceId`, advances `advanceId`, quality `checkId`, daily closing `closureId` (alongside recorded `date`), and cashier `/cashier-journals/:id`. Preserve the query's `branchId` and let source pages and their existing API endpoints authorize/deep-link the requested record. If a source page does not yet consume the listed query parameter, it must implement ID hydration there, rather than presenting an unrelated list as a record detail.

`daily` shows seven dated evidence days: opening completion from recorded branch shifts, closure state from persisted daily closures, and journal count from dated cashier journals, each only with its own source grant. Missing opening record is `unavailable`, not a historical assertion that the branch was closed. `weekly` is the rolling seven-day aggregate of these persisted dated rows, always partial coverage because there is no separate weekly close or snapshot. Other cards represent current state and must never be repurposed as history. Operations and export responses are `no-store`.
