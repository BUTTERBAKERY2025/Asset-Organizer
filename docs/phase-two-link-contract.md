# Phase 2 explicit production coverage contract (development only)

An advanced plan remains independent unless its item is explicitly linked. One plan item links to at most one approved REAL central-kitchen request item, for **its entire targetQuantity** (positive integer); multiple items may link to one request only while their summed targets plus active direct batches do not exceed requestedQuantity. No partial allocations, unit conversion, inferred/historical links, material reservation, or stock movement is performed by linking.

`PUT /api/advanced-production-orders/:orderId/items/:itemId/request-link` body `{ "requestItemId": positiveInteger, "reason": nonempty string (max 500) }`; production `edit` permission and access to both source kitchen and request kitchen required. A byte-for-byte same persisted link (item/request/reason) returns 200 replay; new link returns 201. A different existing link returns 409. `DELETE` same path removes a link **only before any advanced batch exists, or when all its batches are cancelled**; deletion is idempotent (204). GET `/api/advanced-production-orders/:orderId/execution` includes `requestLink: {requestItemId, requestOrderId, requestedQuantity, allocatedQuantity, reason} | null` per item. GET `/api/production/planning` includes the same `requestLink` on advanced-plan items and `linkedAdvancedPlans: [{planItemId, planOrderId, allocatedQuantity, reason}]` on request items.

UI selector: `GET /api/advanced-production-orders/:orderId/items/:itemId/request-link/candidates?limit=50&offset=0` (production `view` and authorized plan source kitchen). `limit` integer 1–100; `offset` integer 0–10000. Response `{ candidates: [{requestItemId, requestOrderId, requestNumber, requestBranchId, kitchenId, neededDate, productId, unit, requestedQuantity, availableQuantity, alreadyLinked}], limit, offset, truncated, nextOffset, availabilityBasis }`. Exact server-filtered eligible approved REAL request items for this plan's source kitchen + target requesting branch, finished product/unit, end-date and integer available target; `alreadyLinked` includes current item even when free available is below target. `availableQuantity` = request quantity minus active direct batches and **all** linked plan targets; not free inventory, reservation or promise of fulfillment. `truncated` means fetch next page; do not infer completeness from the generic planning grid. A create call must still revalidate under the DB lock and can return 409 if another writer wins.

Every newly executed advanced batch freezes `advancedRequestItemId` at creation (null for an independent plan), and each execution GET batch object includes `requestItemId`. This immutable batch-level provenance survives an all-cancelled unlink; it does **not** reclassify finished ready stock as outstanding in-progress production.

Coverage read now exposes optional `item.coverage.linkedAdvancedPlanned`: the eligible **unstarted** linked target portion left after free stock and active batches are assigned. It is neither free stock nor guaranteed in-progress output; finished advanced units are removed from this planned portion and participate only in ready-stock availability. `remainingProductionNeed` excludes that prospective plan portion, while `prospectiveInProgress` represents active batches only. Direct demand read also distinguishes `linkedAdvancedPlannedQuantity` and `linkedDirectFinishedQuantity`; finished direct output constrains any new direct production despite already being normal ready stock.

The operations-board `uncoveredQuantity` is now the **actionable direct-batch maximum** (capped by linked plan targets and finished direct production), not a physical shortfall guarantee. `physicalUncoveredQuantity` separately preserves the pre-cap free-stock allocation estimate for display; do not label `targetQuantity - uncoveredQuantity` as guaranteed stock.

Link requires an approved REAL request, matching finished product and unit, plan source equal to request central kitchen, plan target equal to requesting branch, noncancelled approved/in-progress plan and noncancelled item; plan end must be on/before request needed date. The plan item's full target plus direct active request batches and other linked targets cannot exceed requestedQuantity. A plan item with any batch (including cancelled) cannot be newly linked or reassigned. A cancelled **batch** frees its quantity within its linked plan; the full target remains allocated until explicit unlink, permitted only when all its batches are cancelled. Unlink frees its full allocation without reversing inventory. Finished output is posted once to ordinary ready stock, never also classified as in-progress coverage. Existing independent plans and direct request execution routes remain available; no retroactive matching is done. 400 invalid input, 403 scope, 404 missing item, 409 conflicting eligibility/coverage/immutability, 503 missing migration. Production schema migration must be reviewed/applied manually before deploying dependent code.
