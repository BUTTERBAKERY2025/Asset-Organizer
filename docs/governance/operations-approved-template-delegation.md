# إسناد قوالب الفروع بواسطة مدير التشغيل

## قاعدة العمل
لا يقتصر المسار على قالب الكاشير أو مفتاح معين. تشمل التغطية تلقائيًا جميع الموظفين النشطين الحاليين والجدد في فروع مدير التشغيل المصرح بإدارتها والكتابة فيها، دون اختيار بالاسم. التغطية لا تنشئ حسابات أو تسند صلاحيات تلقائيًا؛ يظل إنشاء الحساب أو تحديثه بالقالب إجراءً صريحًا.

تعرض واجهة الأدمن التغطية للقراءة فقط. طلب حفظ الاختيار القديم يُرفض برسالة توضح أن النطاق أصبح تلقائيًا، دون تعديل الاختيارات التاريخية أو الحسابات.

الحساب العادي القديم الذي لا يحمل إسنادًا سابقًا ويمكن التحقق من صلاحياته المباشرة ضمن نطاق وحدات الفروع المدعومة يمكن مراجعته وإسناد قالب له. الربط القديم المتضرر أو المعدّل، والاستثناءات والصلاحيات الموروثة غير المعروفة، لا تُعامل كحساب قديم آمن لتجاوز الحماية.

الإصدار المعتمد مصدر صلاحيات القالب؛ قائمة الصلاحيات اليدوية القديمة لا تصفّي محتواه ولا تمنع تبديله بقالب معتمد آخر. مفتاح تشغيل التفويض ما زال لازمًا. لم يتغير سقف الطلبات اليدوية القديمة، ولم يُسمح للمدير بتعديل القوالب أو اعتمادها أو ترقية أدوار الحسابات.

## الحدود
- آخر إصدار يجب أن يكون معتمدًا، وجهة الإسناد «مدير التشغيل المفوض أو المسؤول».
- قوالب الأدمن فقط والنطاقات غير المدعومة لا تُمنح تلقائيًا. القائمة تعرض أسباب الاستبعاد.
- جميع قوالب الأسماء والوظائف تستخدم فحص الإجراءات نفسه، لا شرط اسم «كاشير».
- الإجراءات المدعومة حاليًا هي إجراءات وحدات الفروع السابقة، وعرض القائمة والتفاصيل، وصلاحيات العرض للصفحة الرئيسية ولوحة التحكم والكاشير وأدائه والحوافز والتحديات والعمولات ومكافأة الفرع ومحفظة النقاط. لا يشمل ذلك إدارة مستخدمين أو صلاحيات عامة غير مراجعة.
- تسمية النطاق لا تضمن تقييد كل مسار قديم بالفرع. ضوابط الموارد والأدوار والبيانات الأصلية تبقى نافذة، ولا تضاف فروع للحساب.
- الحسابات الإدارية أو متعددة الفروع، والأدوار الموروثة والاستثناءات غير المعروفة، لا تُتجاوز حمايتها.

## استمرارية إدارة الحساب
يسمح للحساب ذي القاعدة الأوسع بالبقاء قابلًا لإدارة العمليات فقط عندما تطابق الصلاحيات الفعلية المخزنة الإصدار المسند، ويكون الاعتماد وربط الحساب والموظف والفرع ومصدر الصلاحيات سليمة. التلاعب بالقاعدة أو نقل الربط يعيد الحماية بدل اعتماد البيانات المتبقية.

إنشاء إصدار جديد لا يحدّث حسابات الموظفين تلقائيًا. يبقى الإصدار المسند السابق مرجعًا حتى إسناد جديد صريح. الإضافات المستقلة والرفض لا تُمسح عند تغيير القاعدة.

## التحقق والنشر
التحقق الأحدث للتغطية التلقائية: 216 تحقق HTTP ناجح على قاعدة مؤقتة مملوكة، و198 اختبار سياسة ومسارات، و135 اختبار واجهة. أكّد المتصفح بحساب الأدمن عرض تغطية المدير والبحث والتصفية والتحديث دون أي طلب حفظ، وبحساب المدير ظهور الموظفين المرتبطين وغير المرتبطين دون واجهة الأدمن. اختُبرت حماية نقل الموظف إلى فرع آخر، وفروع القراءة، والأدوار الإدارية، والتلاعب بقاعدة القالب حتى بإضافة صلاحية فرع معروفة. لم تُشغّل حزمة اختبارات قاعدة البيانات القديمة كاملة ضمن هذا التحقق؛ الأعداد تخص الحزم المحددة المذكورة.

### التحقق السابق لإسناد القوالب
لا ترحيل جديد ولا تعديل حسابات حية. التغيير يُنشر بالشيفرة على Render. اختبار HTTP مع قاعدة مؤقتة مملوكة وخادم حقيقي نجح في 207 تحققات، تشمل إنشاء حساب وتسجيل دخوله، تبديل قالبين مختلفين، بقاء الحساب قابلًا للإدارة، تفسير الاستبعاد، رفض فرع آخر وحماية قاعدة تم التلاعب بها. اختبارات السياسة والمسارات: 197 ناجحًا؛ اختبارات الواجهة: 130 ناجحًا. فحص الأنواع للملفات الخلفية المعدلة بلا أخطاء.

اختبار المتصفح نجح بحساب مدير تشغيل: إسناد قالب وتبديله بقالب مختلف لحساب قائم (200)، وإنشاء حساب موظف آخر (201)، ثم إعادة القراءة وتسجيل الدخول لكل منهما. بقيت بيانات دخول الحساب القائم صالحة، وظهرت أسباب استبعاد قالب إدارة المستخدمين. اختبارات التلاعب بالقاعدة وفرع آخر مؤكدة في اختبار HTTP المعزول، وليست جزءًا مكتملًا من اختبار المتصفح.

ملاحظة حدود المحتوى: منح صفحة أداء الكاشير دون يومية الكاشير لا يمنح بيانات اليومية ضمنيًا؛ قد تظهر الصفحة بينما ترفض واجهات اليومية بيانات التقرير. لم تُضف صلاحيات غير مختارة لتجاوز هذه التبعية.
