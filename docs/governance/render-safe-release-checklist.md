# تجهيز نشر إصلاحات الصلاحيات على Render

تاريخ الفحص: 2026-10-02. **الإعداد المحلي مكتمل؛ لم يحدث نشر أو إعادة تشغيل أو كتابة لقاعدة الإنتاج.**

## أدلة التحقق

- مقارنة الاختبارين المختلف عليهما بنسخة المستودع السابقة لإصلاحات الصلاحيات أعادت الفشلين نفسيهما: توقع نص قديم لتوجيه المطبخ، وبديل صلاحيات فروع يعيد قائمة فارغة.
- تم تحديث الاختبارات فقط، دون تعديل منطق التطبيق: اختبار التوجيه يفحص المساعد الحالي وحالات المنع/المباشر، واختبار الملفات يحاكي منح الفرع الحديثة ثم سحبها رغم بقاء الفرع في الطلب.
- الاختباران نجحا: 9/9. حزمة الإصلاحات السابقة 981/981 ما زالت صالحة لأن هذه الخطوة لم تعدل التطبيق أو ملفات تلك الحزمة. هذه نتائج تشغيل منفصل، وليست ادعاء تشغيل جميع اختبارات المستودع.
- `npm run build` نجح بالكامل: واجهة Vite، والخادم `dist/index.cjs`، وملفات كتالوج الإنتاج الثلاثة.
- ملف القفل لا يحتوي روابط `package-firewall.replit.local`. لم نختبر تثبيتًا جديدًا داخل Render.
- توجد تحذيرات غير مانعة عن حجم الحزم والاستيرادات المزدوجة وطرق/مفتاح مكرر؛ ليست فشل بناء، ولا يعني نجاح البناء نجاح فحص TypeScript شامل.
- GET عام لـ `https://thebutterbakery.com/api/health` أعاد healthy وdatabase connected.
- GET عام لـ `/api/version` أعاد `2026-02-23-v3` ومعرف بناء `1790947971336`. هذا **ليس Commit SHA** ولا يثبت أن الإصلاحات منشورة.
- البناء المحلي يضع نطاق المعاينة في صورة المشاركة عبر إضافة meta-images؛ لا يُنقل dist المحلي إلى Render. يعاد البناء من المصدر في بيئة Render وتُراجع عناوين البيانات الوصفية هناك.

## قرار الجاهزية

مرشح المصدر يجتاز البناء والاختبارات المحددة. **النشر الفعلي معلق** إلى حين توثيق نسخة الخدمة الحالية والنسخة المرشحة، وتجربة تشغيل آمنة على قاعدة اختبار، والتحقق من النسخ الاحتياطي وخطة الرجوع. تأكيد صاحب النظام لربط Render بمشروع Supabase سبق توثيقه، فلا يُطلب مجددًا دون دليل متعارض.

## خطوات مسؤول النشر — لا تُنفذ تلقائيًا

### قبل النشر

1. تسجيل الخدمة التي تخدم الدومين الفعلي، وCommit SHA لآخر نشر ناجح، وإعدادات البناء والتشغيل الحالية غير السرية. لا نسخ متغيرات الاتصال أو المفاتيح.
2. تثبيت Commit SHA للمرشح المحتوي على الإصلاحات والاختبارات، ومراجعة الفرق عن النسخة الحية حتى لا تُنشر تغييرات أخرى غير مراجعة.
3. التأكد من عدم تشغيل نشر تلقائي بمجرد دفع المرشح؛ لم يُدفع شيء في هذه الخطوة.
4. التحقق من نسخة احتياطية حديثة وإجراء استعادة معروف. الرجوع للتطبيق وحده لا يعكس تغييرات قاعدة البيانات.
5. تشغيل المرشح أولًا في بيئة منفصلة بقاعدة اختبار وبيانات وهمية. بدء التطبيق الحالي ينفذ إجراءات قاعدة بيانات تلقائية؛ عدم إضافة migration في هذه الدفعة لا يجعل بدء التطبيق خاليًا من الكتابة.
6. فحص الوظائف المشروعة: admin يدير الصلاحيات، ومفوّض التشغيل يدير الموظفين المسموحين فقط. التأكد من 403 لغير المفوض، و404 لمالك الإسناد غير المطابق، ومنع حذف الوثيقة دون delete مع بقاء البيانات.
7. مراجعة أثر منع users:edit وحدها من إدارة السلطة العامة؛ لا إعادة تطبيق قوالب أو سحب منح مخزنة تلقائيًا.

### إعدادات البناء المرشحة

- البناء المحلي المثبت: `npm run build`؛ يحتوي `dist/index.cjs` و`dist/public` و`dist/catalogue-source`.
- أمر التشغيل في package.json: `npm start`، ويشغل `NODE_ENV=production node dist/index.cjs`.
- هذه أوامر المستودع، وليست إثباتًا لإعدادات Render الحالية. تُقارن بالإعدادات الحالية قبل أي تعديل.
- لا `db:push`، ولا إعادة تهيئة أدوار، ولا سكربت تحويل حسابات ضمن هذه الدفعة.

### عند اعتماد النشر

1. اعتماد نافذة نشر وخطة رجوع، ثم نشر المرشح المحدد على خدمة Render الحالية؛ لا نشر مشروع Replit المختلف.
2. متابعة سجل البناء وبدء التشغيل، ومنع إعلان النجاح إذا ظهر فشل جاهزية مخطط أو اتصال أو تخزين.
3. تأكيد Commit SHA المنشور من تفاصيل نشر Render، وفحص health/version، ثم فحص الوظائف المعتمدة بحسابات اختبار مصرح بها، لا تعديل حسابات الموظفين الفعلية.
4. مراقبة 403 غير المتوقعة و5xx وشكاوى الوصول بعد النشر.

### الرجوع

- عند تعطل الدخول أو الوظائف المعتمدة: إيقاف التوسع والرجوع إلى آخر إصدار ناجح موثق للخدمة وفق آلية Render المتاحة.
- لا استعادة قاعدة بيانات تلقائيًا فوق معاملات المستخدمين الجديدة. إذا كانت إجراءات البدء قد غيرت القاعدة، يُقيّم التوافق أولًا ويُعتمد إجراء منفصل.
- الرجوع للإصدار السابق قد يعيد الثغرات الثلاث؛ ليس إصلاحًا أمنيًا، ويحتاج احتواء وصول مؤقتًا معتمدًا.

## معلومات ما زالت مطلوبة

- Commit SHA للنسخة الحية وإعدادات الخدمة الفعلية. أفاد المستخدم أن المعرف غير متوفر لديه ولم يفهم طريقة استخراجه؛ يُطلب دليل مبسط مثل صورة تفاصيل آخر نشر ناجح دون أسرار، بدل إعادة السؤال التقني نفسه.
- أكد المستخدم في 2026-10-02 وجود نسخة احتياطية حديثة وطريقة استعادة معروفة. هذا تأكيد مالك الخدمة، وليس تحققًا مستقلًا من تاريخ النسخة أو نجاح تجربة استعادتها.
- نجاح بدء المرشح ومساراته في بيئة قاعدة اختبار منفصلة.
- موافقة النشر النهائية؛ هذا المستند ليس تصريحًا بالنشر.
