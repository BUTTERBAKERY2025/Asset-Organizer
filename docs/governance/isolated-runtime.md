# تشغيل اختبار محلي معزول قبل نشر Render

## النتيجة المثبتة

بتاريخ 2026-10-02 نجح تشغيل **الخادم الفعلي وPostgreSQL 16.10** محليًا ببيانات وهمية، باستخدام مصادقة كلمة المرور والجلسات العادية، دون اتصال بقاعدة الإنتاج أو موارد سحابية جديدة. أُوقفت العمليات وحُذفت القاعدة المؤقتة عند نهاية التشغيل.

- 8 اختبارات بناء المخطط المعزول.
- 8 اختبارات عملية لرفض الاتصالات غير المسموحة، وإثبات العزل، وعدم تأثر استيراد الخادم بصيغة الإنتاج CJS.
- 42 حالة تحقق عبر HTTP حقيقي في الاختبار الكامل.
- بناء الإنتاج `npm run build` ناجح، مع تحذيرات الحزم والتعريفات المكررة الموجودة سابقًا.

هذه ليست تجربة واجهة متصفح، ولا شهادة بأن كل الجداول ومزودي الخدمات في الإنتاج مماثلون لقاعدة الاختبار. اختبارات مصفوفات الأدوار السابقة تبقى مكملة لهذا الفحص.

## الاستخدام

يشغَّل من جذر المستودع بعد تثبيت الاعتماديات. الأدوات PostgreSQL `postgres`, `initdb`, `pg_ctl` مطلوبة في PATH؛ كانت مثبتة في البيئة ولم نثبت حزمًا جديدة.

```sh
# اختبارات الحماية وتوليد المخطط؛ لا تشغّل التطبيق أو تتصل بالإنتاج
npm run test:isolated

# قاعدة محلية جديدة + مخطط + بيانات وهمية + تحقق + حذف تلقائي
npm run test:isolated:prepare

# كل ما سبق، ثم تشغيل الخادم واختبارات HTTP وتسجيل الدخول، ثم الإيقاف والحذف
npm run test:isolated:smoke
```

لإنشاء ملف SQL فقط دون تطبيقه:

```sh
./node_modules/.bin/tsx scripts/isolated-test/baseline-generate.ts --out /tmp/new-isolated-baseline
```

الدليل الناتج يجب أن يكون جديدًا. لا تطبق هذا المخطط على قاعدة موجودة أو الإنتاج، ولا تستخدم `db:push`.

## ما الذي يمنع الوصول إلى الإنتاج؟

1. ينشئ المنسق عنقود PostgreSQL جديدًا داخل دليل مؤقت خاص 0700، بمنافذ محلية وأسماء عشوائية. لا يختار اتصالًا من DATABASE_URL أو SUPABASE_DATABASE_URL.
2. ينشئ دورًا مؤقتًا ليس superuser ولا يملك إنشاء أدوار/قواعد أو تجاوز RLS، ويكتب سجل ملكية خاصًا 0600.
3. قبل التطبيق وإعادةً قبل الكتابة، يتحقق بعملية قراءة فقط من اسم القاعدة ومالكها ودورها وعلامتها ومقبسها، ثم رقم هوية عنقود PostgreSQL ودليل بياناته مقابل السجل المحلي المملوك.
4. لا يقبل المدخل عناوين بعيدة، حتى لو سُمّيت staging، ولا يستخدم عنوان الإنتاج كبديل عند نقص الإعدادات.
5. يبني بيئة العملية بقائمة سماح، ولا يورث مفاتيح خدمات الإنتاج. كلمات مرور الاختبار ومفتاح الجلسة تولَّد لحظيًا، ولا تُطبع أو تُحفظ في المستودع.
6. اعتراض شبكي داخل Node يمنع الاتصالات غير المسموحة وDNS للأسماء والخدمات الخارجية والعمليات الفرعية داخل التطبيق. يسمح فقط بمقابس الاختبار المحددة وDNS الحرفي للـ loopback اللازم لـ listen.
7. وضع الاختبار لا يغيّر التفويض أو يدخل المستخدم تلقائيًا؛ يفصل تشغيل الجدولة والتخزين وVite والاستدعاءات الدورية عن الخادم المختبر.
8. التشغيل العادي لا يحمّل أدوات الاختبار. اختبار CJS ينفذ استيراد الوحدة في دليل فارغ بلا ملفات الاختبار للتأكد من ذلك.

الحماية موجهة إلى أخطاء التشغيل والاتصالات العادية، وليست عزل نظام تشغيل ضد شفرة native خبيثة. لا تدعم التشغيل البعيد أو نشر وضع الاختبار في Render.

## مصدر المخطط ومدى مطابقته

`scripts/isolated-test/baseline.ts` يولد الجداول من مخطط Drizzle المثبت ببصمات SHA256، ويضيف الترحيلات المختارة ذات الوظائف والمشغلات والقيود الضرورية. `baseline.sources.json` يثبت المصادر، والملف الناتج يتضمن manifest يبين الاستثناءات والترحيلات المستبعدة.

يشمل التأسيس جدول الجلسات ومتطلبات جاهزية 039 و043 و044 المحصّنة. تُنفذ استعلامات الجاهزية نفسها المأخوذة من `server/index.ts`، ولا يُعتبر وجود الجداول وحده كافيًا. تطبيق المخطط معاملة واحدة يرفض public غير الفارغ. لا توجد قراءة لصفوف الإنتاج أو نسخ بيانات موظفين أو اشتراكات Push أو رسائل.

**استثناء معلن:** المخطط الحالي يصف campaign_expenses.branch_id كعدد صحيح بينما مرجع branches.id نص. رفض PostgreSQL إنشاء هذا المفتاح الأجنبي. لذلك يصحح مولد الاختبار نوع العمود في النسخة الفارغة المولدة فقط إلى varchar، مع إبقاء المفتاح الأجنبي، ويتحقق من الشكل المتوقع قبل التصحيح. لم تتغير shared/schema.ts أو قاعدة الإنتاج. توجد كذلك تسوية معلنة لقيد سبب الربط في 044 ضمن المخطط المولد. الاستثناءات تمنع وصف القاعدة بأنها نسخة مطابقة للإنتاج.

إذا تغير مصدر مثبت، يفشل التوليد. يجب مراجعة أثره وتحديث البصمات/قائمة الترحيلات صراحةً، لا تجاوز الفحص أو تحديث كل البصمات عميانيًا.

## الحالات التي اختُبرت عبر HTTP

- دخول admin والمستخدم المحدود ومدير التشغيل والموظف والحساب المفوض المنشأ أثناء التجربة، بالمصادقة العادية.
- G01: رفض المنح العامة والتعديل الذاتي لغير المفوض، مع ثبات بيانات الصلاحيات ونجاح عملية الأدمن.
- G02: إسناد صحيح للأدمن، رفض الكتابة العامة لغيره، رفض عدم تطابق المالك وبقاء الإسناد دون تعديل، وحذف مشروع للأدمن.
- G03: مستخدم view-only يقرأ الوثائق، ولا ينفذ POST/PATCH/DELETE حين يُستنتج الإجراء. تغطية خرائط الأدوار التلقائية الشاملة موجودة في اختبارات الصلاحيات المعزولة السابقة.
- اختيار موظفي التفويض وحدود الفرع والسقف الممنوح، وتعارض المراجعات القديمة، وإنشاء الحساب في نطاقه.
- التعليق وإبطال الجلسة السابقة، وإعادة التفعيل والدخول الجديد دون إعادة إحياء الجلسة القديمة.

## التنظيف والتشخيص

`ephemeral.mjs` يوقف الخادم ثم عنقوده المؤقت ويحذف دليله الخاص عند النجاح والفشل والإشارات المدعومة. `--serve` للاستكشاف اليدوي يبقى عاملًا حتى إيقافه، وهو API-only. لا ينفذ التنظيف حذفًا في أي قاعدة إعدادات موجودة.

SIGKILL أو توقف الحاوية فجأة قد يمنع التنظيف؛ عندها افحص دليل `isolated-test-cluster-*` الذي يخص التشغيل نفسه وسجله قبل إيقاف عنقوده المحدد. لا تستخدم أوامر قتل عامة أو حذف مجمع للدلائل.

التشخيص يعرض رموز رفض وSQLSTATE، لا عناوين اتصال ولا كلمات مرور. سجلات التطبيق قد تعرض هويات الاختبار الوهمية؛ لا توصل هذه الأدوات ببيانات فعلية.

## حدود النشر

هذا المسار يزيل عائق اختبار بدء الخادم والمصادقة والصلاحيات على قاعدة مستقلة. لا ينشر شيئًا على Render، ولا يختبر تكامل التخزين والمراسلات الخارجي أو واجهة المتصفح. اعتماد النشر ومراجعة إعدادات خدمة Render ونسخة الرجوع خطوات منفصلة في render-safe-release-checklist.md.
