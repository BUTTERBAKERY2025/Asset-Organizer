# المرحلة الخامسة: إضافات الأدمن المستقلة

## المنفذ

- إدارة مستقلة للأدمن داخل حسابات الموظفين: إنشاء منح أو رفض، تعديله وحذفه مع السبب، ومراجعة نطاقه وبدايته ونهايته الاختياريتين.
- الإضافات لا تكتب في أساس القالب. مدير التشغيل يراها للقراءة فقط، وتبقى عند تبديل القالب أو خفض الأساس.
- تستخدم الاستثناءات القائمة كمصدر صلاحية، لا محرك تفويض موازيًا. معلومات المصدر تربط الاستثناء بالموظف والحساب والفرع وتكشف تغيير السجل خارج مسار الإدارة المستقلة.
- الكتابة تتحقق من الأدمن ومن تطابق الموظف والحساب والسجل، وتحفظ التدقيق وإبطال الجلسات والتغيير في المعاملة نفسها. التعديل والحذف يتطلبان نسخة مراجعة مطابقة؛ التعارض يحتفظ بمسودة الشاشة ويطلب تحديثًا وتأكيدًا جديدين.
- بصمة تأكيد تبديل القالب تشمل الإضافات؛ لا يعتمد المدير معاينة قديمة بعد تغيير الأدمن لها. فرق الصلاحيات المعروض في اختيار القالب يخص الأساس فقط.

## حدود النطاق والحماية

النطاق العام معلن بوضوح وليس مقيدًا بفرع ضمنيًا. النطاق الفرعي متاح فقط لإجراءات وثائق الموظفين والتقييمات التي تتحقق مساراتها من السياق بالفعل، وفي فرع الموظف المسجل. لا تُعرض نطاقات وهمية لوحدات التشغيل القديمة غير المهيأة لذلك.

الإضافة الإدارية الحساسة أو خارج سقف التفويض، والاستثناءات القديمة غير الموثقة، والسجل الذي تغير خارج مسار الإضافات، تبقي الحساب محميًا من مدير التشغيل. لا تخفيف شامل لحماية الاستثناءات أو الإسنادات.

الرفض القديم لا يُحوّل إلى منح ولا يُحذف ولا يُتبنى تلقائيًا. المنح المستقبلي لا يعمل قبل موعده، والمنتهي لا يعمل بعد نهايته، حتى عند غياب سجل المصدر. صلاحيات الأدمن القائمة لم تُقيّد.

## التشغيل

الترحيل `054_employee_account_additions.sql` معدّ للتطبيق اليدوي فقط مع متطلبات المراحل السابقة. يتضمن تاريخ بداية الاستثناء وسجل مصدر الإضافات. لا ترحيل للحسابات، ولا تعبئة أو اعتماد أو إسناد تلقائي.

لم يُطبق هذا الترحيل على قاعدة التشغيل أو الإنتاج. اختبارات HTTP تستخدم PostgreSQL مؤقتًا مملوكًا ومعزولًا، ولا تعد دليل نشر.

## التحقق

- 255 اختبارًا مركزًا للخادم والسياسة والتفويض وخط الأساس.
- 98 اختبارًا للواجهة، تشمل الإنشاء والتعديل والحذف، فروقات الأساس، العرض غير القابل للتعديل لمدير التشغيل، التعارض وتواريخ الصلاحية.
- نجح التحقق المركز على PostgreSQL مؤقت وخادم التطبيق الحقيقي: 114 تحقق HTTP، يشمل تبديل الأساس مع حفظ الإضافات، الرفض والتواريخ، التراجع عند فشل التدقيق أو الجلسات، ونطاق وثائق HR ورفض الفرع الآخر.
- كشف الاختبار الفعلي اختلاف فك ترميز أعمدة الوقت بين القراءة الخام وDrizzle؛ وُحّد فك الترميز باستخدام تعريف الأعمدة نفسه، دون تخفيف فحص سلامة المصدر. غُطي الرجوع عبر قاعدة البيانات بثلاث مناطق زمنية.
- فحوص TypeScript المركزة ناجحة، دون ادعاء نظافة المشروع بالكامل.
- نجح بناء الإنتاج بعد تصحيح فك ترميز الوقت. الجولة الشاملة لم تكتمل بنجاح؛ التحليل الفعلي النهائي لهذه المرحلة هو الجولة المركزة المذكورة، وليس ادعاء نجاح جديد لكل الاختبارات السابقة.
- نجح المتصفح الفعلي في إنشاء الإضافة وتعديلها كأدمن، ثم إسناد القالب كمدير تشغيل مع بقاء الرفض مستقلاً للقراءة فقط، ثم حذف الإضافة كأدمن والتحقق من بقاء أساس القالب كما هو. إعادة التحقق اقتصرت على المسار الذي تأثر بتصحيح الوقت.

## ملاحظة تحقق

استُدعي اختبار PostgreSQL قديم بالخطأ قبل حمايته، واستعمل مخطط اختبار مؤقتًا في قاعدة التطوير ثم نظّفه. لم تنجح مجموعته لأن تجهيزاتها سبقت منع إنشاء الحساب الخام لمدير التشغيل. أضيف شرط إثبات ملكية قاعدة الاختبار قبل الكتابة، ولم تُحتسب هذه المجموعة ضمن الاختبارات الناجحة. لا تشغّل اختبارات قواعد بيانات قديمة لمجرد أن اسمها يحتوي integration أو isolated.
